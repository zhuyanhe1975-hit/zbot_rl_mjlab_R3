## 已确认与未确认

500轮模型有效速度指令正常，双足和蛇形运动状态均保持100%。扩大回放速度仍不能使双足行走：

| vx请求 | 双足实测vx | 蛇形实测vx |
| --- | ---: | ---: |
| .05m/s | -.000069m/s | -.000185m/s |
| .15m/s | -.000383m/s | -.000064m/s |
| .30m/s | -.000245m/s | .003823m/s |

双足平均绝对动作约`.32–.36`，随指令改变；这不是无动作输出，而是输出了不能持续推进的姿态。不能用“默认速度太小”“阶段还没切好”或“只需继续增加轮数”解释。

读取100轮检查点，在1000个训练配置环境中收集24步；只计算PPO梯度，没有执行优化器更新：

| 任务 | 样本数 | 原始优势std | 全局归一化后std | 任务平均损失的Actor梯度范数 |
| --- | ---: | ---: | ---: | ---: |
| 双足运动 | 9600 | .0881 | .3248 | .1145 |
| 蛇运动 | 9600 | .3697 | 1.3627 | .4539 |
| 起立 | 2400 | .1901 | .7009 | .6462 |
| 下降 | 2400 | .2081 | .7673 | .6529 |

不同任务之间的梯度余弦约`-.014至-.042`，接近正交，不能据此宣布强烈梯度冲突是根因。双足的训练信号相对较弱是测到的事实，但本轮没有把改变优势归一化、扩网或换算法当成已验证修复。Beta采样／logprob、PPO更新、Actor/Critic归一化以及59维命令/阶段输入均未发现硬接口错误。

此前`Episode_Metrics/phase_*`是**刚结束回合的环境子集**的均值，短失败回合会占据日志；85%起立不能解释成85%采样都给起立。旧运动误差又先跨全环境缩放再按重置子集聚合，同样不能作为真实跟踪误差。本次删除教师中这些回合指标，改在每次PPO更新前统计完整rollout的四任务帧数／占比、有效运动帧数、各轴RMSE及沿指令方向速度。指标只写TensorBoard，不增加终端阶段输出或100轮验收。

## 用现有两个入口做单技能对照

为区分“基础运动配方不易学习”和“联合训练不易学习”，使用相同Wide-Biped任务、网络、PPO和运动奖励，隔离构型。修复了固定`stand/snake`训练模式下物理初态仍随机的问题：对照现在100%从指定构型开始，且不采样变形任务。

双足对照：

```bash
ZBOT_SKILL=biped bash train.sh --agent.max-iterations 100
ZBOT_SKILL=biped bash run.sh
```

蛇形对照：

```bash
ZBOT_SKILL=snake bash train.sh --agent.max-iterations 100
ZBOT_SKILL=snake bash run.sh
```

100轮是有界的首轮诊断窗口，不是成功承诺。对照结果尚未取得；不能先宣称问题已解决。若独立运动仍没有进展，应继续核对相对于成功归档的动作分布、位置控制与积分控制差异；若独立运动学会而联合停滞，再用联合优化／容量对照检验原因。

`ZBOT_SKILL`省略或设为`omni`仍为全能联合训练。双足与蛇形对照分别保存在`logs/ablations/biped/`、`logs/ablations/snake/`，回放使用相同选择，避免误载联合模型。没有新增启动脚本。

本轮未停止用户正在运行的训练，也未启动对照训练。

原始数据：`outputs/diagnostics/fsm_model100_probe.json`、`fsm_model500_probe.json`、`fsm_model100_role_gradients.json`。
